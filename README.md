# 贷款调查报告质量评价系统

把授信审批部原来分散在线下 Excel 台账里的「调查报告主观评价」搬到线上：统一六维评分口径、
沉淀退回原因、按机构 / 客户经理 / 审查人员多维统计分析。单容器 Docker 部署，内网离线可用。

---

## 一、快速开始

### 方式一：Docker（推荐，内网部署）

```bash
# 在有外网的机器上构建镜像（或使用内网镜像仓库）
docker compose up -d          # 构建 + 启动，监听 3000 端口
# 或者分步执行：
docker build -t loan-report-qas:1.2.0 .
docker run -d --name loan-report-qas -p 3000:3000 -v "$PWD/data:/app/data" loan-report-qas:1.2.0
```

- 首次启动自动建库并灌入演示数据（8 机构 / 15 员工 / 12 客户 / 24 笔台账）
- 数据库为 SQLite 单文件（`data/app.db`），挂卷持久化；**备份 = 拷贝 `data/` 目录**
- 前端依赖（Vue3 / TDesign / ECharts）已全部本地化到 `web/assets/vendor/`，**容器运行完全离线**，内网无外网可用
- 健康检查：`GET /api/health`

### 方式二：本地开发

```bash
npm install       # 仅 express + xlsx 两个生产依赖（Node ≥ 22.5，内置 SQLite，无原生编译）
npm start         # 启动，访问 http://localhost:3000
npm run seed      # 重置演示数据（--reset 强制重建）
npm run smoke     # API 冒烟测试（需服务已启动，61 项断言）
npm run gui       # 浏览器 GUI 走查（需本机 Chrome，20 项断言 + 截图到 .gui/）
```

## 三、评价体系（两层口径）

```
客户经理撰写调查报告
   └─→ 审批人员审查报告：六项分析质量评分（优100 / 良90 / 中80 / 差70）+ 登记 1~4 次退回原因
          └─→ 审批负责人审查「审批人员的审查工作」：打「审查评价」（优/良/中/差）+ 意见
```

- **审查评价的评价对象是审批人员的审查工作**（评分是否客观、退回登记是否规范），不是调查报告本身；
- **报告得分** = 六项分析质量得分的算术平均（考核客户经理报告质量）；
- **审查评价得分单列**（考核审批人员审查工作质量），不并入报告得分；
- 优良占比 = 报告得分 ≥ 90 的笔数占比。

## 四、功能与台账要素对照

| 原 Excel 台账要素 | 系统字段 | 数据来源 |
|---|---|---|
| 经办机构 | 机构 | 引用「机构管理」 |
| 客户名称 | 客户 | 引用「客户管理」（导入时可自动创建） |
| 上报日期 | 日期 | 手填，支持区间检索与周/月/季/年聚合 |
| 是否核额 | 枚举（已核额 / 未核额） | 单选 |
| 授信金额（万元） | 数值 | 数字输入，千分位展示 |
| 主调查人 / 辅助调查人 / 第一责任人 / 审批人 | 员工 | 引用「员工（用户）管理」 |
| 系统操作 / 信用情况 / 资产负债 / 经营情况 / 用途情况 / 担保情况 质量 | 六个枚举字段 | 优 100 / 良 90 / 中 80 / 差 70 |
| 第一~四次退回原因 | 四个长文本 | 最多登记 4 次，计入客户经理考核 |
| 审查评价 | 枚举 + 意见 | 审批负责人填写，评价对象为审批人的审查工作 |

## 五、角色与权限

- 四种内置角色；权限点分**菜单级**（控制左侧导航）与**动作级**（服务端接口逐一校验）；
- 超级管理员在「角色与权限」页编辑权限矩阵，保存后即时生效（用户刷新后菜单更新）；
- 审批人员只能修改**本人经办**的草稿/被退回记录；审查、退回仅审批负责人可操作。

## 六、工作流

```
① 评价录入（审批人员）──提交──▶ ② 负责人审查评价（审批负责人）──归档──▶ ③ 归档完成
        ▲                              │
        └────────── 退回修改 ──────────┘
```

- 提交后评价内容**锁定**，需负责人退回才能修改；
- 待办 / 已办：审批人员（本人草稿+被退回 / 本人已提交），审批负责人（全部待审查 / 本人已审查）；
- 「工作流管理」页可查看各节点笔数与在途实例停留天数（≥3 天标红）；
- 每笔记录的登记、提交、审查、退回动作全程留痕，在详情页「流转记录」展示。

## 七、统计分析

- 时间维度：按周（ISO）/ 月 / 季 / 年，SQL 实时聚合，支持自定义统计区间；
- 分组对象：按机构 / 按客户经理（主调查人）/ 按审查人员（审批人）；
- 指标：审查笔数、报告平均得分、优良占比、已审查笔数、审查评价平均分、审查评价优良占比、退回次数、授信金额合计；
- 图表：得分趋势（双轴）、各对象对比、报告得分等级分布、六维短板雷达（ECharts，离线降级为明细表）；
- 台账与统计结果均可导出 xlsx；台账支持按原 Excel 列名导入（引用校验、逐行错误报告、去重）。

│   ├── index.html
│   └── assets/
│       ├── vendor/         # vue / tdesign / icons / echarts（离线）
│       ├── css/app.css

## 九、常用运维

```bash
docker compose up -d --build      # 更新部署
docker compose logs -f            # 看日志
docker compose down               # 停止（data/ 目录保留）
# 备份
cp -r data/ backup-$(date +%F)/
# 恢复出厂演示数据（清空后重启即重新灌入）
docker compose down && sudo rm -rf data && docker compose up -d
```
